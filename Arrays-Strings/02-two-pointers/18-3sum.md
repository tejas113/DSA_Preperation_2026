# 15. 3Sum

**LC 15** · **Source:** LC150 + NC150 · **Difficulty:** Medium · **Priority:** Core · **Pattern:** Sort, then two pointers per fixed element

---

## 1. Intuition

Three numbers summing to `0` is Two Sum II ([[17-two-sum-ii]]) with an extra outer loop: fix one number,
then use two pointers to find a pair that cancels it out. Sorting first makes both the pointer logic *and*
duplicate-skipping possible.

* `nums.sort()` makes the two-pointer search valid, and makes equal values sit next to each other so duplicates are easy to spot.
* `for i, a in enumerate(nums)` fixes the first number of the triplet; the other two are found with `l` and `r`.
* `if a > 0: break` — once the smallest remaining number is positive, no triplet of a positive and two larger numbers can sum to `0`, so nothing later can work either.
* `if i > 0 and nums[i - 1] == a: continue` skips a repeated *first* number, so the same triplet isn't built twice starting from two equal `a` values.
* Inside the `while l < r`, `three_sum > 0` means the pair is too big → `r -= 1`; `three_sum < 0` means too small → `l += 1`; equal means a match.
* `while l < r and nums[l] == nums[l - 1]: l += 1` after a match skips a repeated *second* number, so the same triplet isn't recorded twice from one `a`.

**Recall:** sort, fix `a`, two-pointer search for a pair summing to `-a`, skip duplicates at both the outer loop and after a match.

---

## 2. Approach

* **Idea:** reduce 3Sum to `n` runs of the sorted two-pointer 2Sum, one per distinct fixed value, and de-duplicate by only ever skipping *forward* over repeats.
* **Data structure / pointers:** `i` fixes the first element `a`; `l` and `r` are the two-pointer search over the rest of the array, same roles as Two Sum II.
* **Invariant:** `res` never contains the same triplet of values twice, because both duplicate-skip lines only trigger on a value equal to the one just processed.
* **Edge cases:**
  * Fewer than 3 elements → the outer loop's `while l < r` never finds a pair (or never runs), `res` stays `[]`.
  * All zeros (`[0, 0, 0, 0]`) → returns `[[0, 0, 0]]` once, not once per combination.
  * No triplet sums to zero → `res` stays `[]`.
  * All positive, or all negative → `break` (all positive) or the inner search never balances (all negative) — either way, no triplet is added.
  * Negative numbers are required for a triplet to sum to `0` unless everything is `0`.

---

## 3. Code

```python
class Solution:

    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        res = []

        for i, a in enumerate(nums):
            # Early exit: If smallest remaining number > 0, sum can't be 0
            if a > 0:
                break

            # Skip duplicate values for the fixed element a
            if i > 0 and nums[i - 1] == a:
                continue

            l, r = i + 1, len(nums) - 1

            while l < r:
                three_sum = a + nums[l] + nums[r]

                if three_sum > 0:
                    r -= 1
                elif three_sum < 0:
                    l += 1
                else:
                    res.append([a, nums[l], nums[r]])
                    l += 1
                    r -= 1

                    # Skip duplicate values for the second element
                    while l < r and nums[l] == nums[l - 1]:
                        l += 1

        return res


if __name__ == "__main__":
    def normalize(triplets: list[list[int]]) -> set[tuple[int, int, int]]:
        return {tuple(sorted(t)) for t in triplets}

    solution = Solution()
    assert normalize(solution.threeSum([-1, 0, 1, 2, -1, -4])) == {(-1, -1, 2), (-1, 0, 1)}
    assert solution.threeSum([0, 1, 1]) == []
    assert solution.threeSum([0, 0, 0]) == [[0, 0, 0]]
    print("All tests passed")
```

## 4. Dry Run

`nums = [-1, 0, 1, 2, -1, -4]` → sorted: `[-4, -1, -1, 0, 1, 2]`

| Fixed `i` | `a = nums[i]` | `l` | `r` | `three_sum` | Action / result | `res` |
| --- | --- | --- | --- | --- | --- | --- |
| `0` | `-4` | `1`→`4` | `5` | `-3` … | never balances | `[]` |
| `1` | `-1` | `2` | `5` | `-1 + -1 + 2 = 0` | **found** `[-1, -1, 2]`, then `l = 3`, `r = 4` | `[[-1, -1, 2]]` |
| `1` | `-1` | `3` | `4` | `-1 + 0 + 1 = 0` | **found** `[-1, 0, 1]`, then `l = 4`, `r = 3` (loop ends) | `[[-1, -1, 2], [-1, 0, 1]]` |
| `2` | `-1` | — | — | — | `nums[1] == nums[2]` → skip | unchanged |
| `3` | `0` | `4` | `5` | `0 + 1 + 2 = 3` | `> 0` → `r = 4` (loop ends) | unchanged |
| `4` | `1` | — | — | — | `a > 0` → **break** | unchanged |

**Return:** `[[-1, -1, 2], [-1, 0, 1]]`

---

## 5. Complexity

* **Time:** `O(n²)` — sorting is `O(n log n)`, and the outer loop runs up to `n` times with an inner two-pointer scan that is `O(n)` each, so the nested work dominates at `O(n²)`.
* **Space:** `O(1)` extra, not counting `res` and the space Python's sort uses internally (`O(n)` or `O(log n)` depending on implementation).

---

## 6. Recall (30 seconds)

* **Reduction:** 3Sum = sort, then `n` runs of the sorted two-pointer 2Sum.
* **Two duplicate skips:** `if nums[i - 1] == a: continue` (same first number); `while nums[l] == nums[l - 1]: l += 1` after a match (same second number).
* **Early stop:** `if a > 0: break` — nothing later can help once the smallest number left is positive.
